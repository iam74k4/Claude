# git-commit

コミット作成は必ず次の手順で行う。ルールの詳細は `~/.claude/rules/git.md` に従う。

## 手順

1. **状態確認**: `git status` と `git diff`(ステージ済みは `git diff --cached`)で全変更を把握する。
2. **ブランチ確認**: 現在のブランチが `main` / `master` なら、コミットせずに
   作業ブランチの作成を提案する。
3. **分割判断**: 変更に複数の意味的単位(機能追加 + 無関係なリファクタリング等)が
   混在していないか確認する。混在していればコミットを分けることを提案し、
   ファイル単位または `git add -p` で分割ステージする。
4. **安全確認**: 差分に秘密情報(API キー・トークン・パスワード・`.env` の内容)や
   デバッグ用コード(`console.log`、`print` デバッグ、コメントアウトの残骸)が
   含まれていないか確認する。見つけたら指摘して除外する。
5. **ステージ**: 対象ファイルを明示的に `git add <file>...` する(`git add -A` は使わない)。
6. **メッセージ作成**: 英語・Conventional Commits 形式で作成する。
   - 1 行目: `<type>: <summary>`(72 文字以内・命令形。例: `feat: add login rate limiting`)
   - 「なぜ」の説明が必要な変更なら、空行を挟んで本文に書く。
7. **コミット後**: `git log -1 --stat` で意図どおりか確認する。

## してはいけないこと

- 差分を見ずにコミットする
- 複数の無関係な変更を 1 コミットにまとめる
- `--amend` をプッシュ済みコミットに対して使う(自分専用ブランチを除く)
