# git-pr

PR の作成・更新は必ず次の手順で行う。ルールの詳細は `~/.claude/rules/git.md` に従う。

## 手順

1. **前提確認**: 対象ブランチが最新の `main` を取り込んでいるか確認する
   (`git fetch origin main` → 遅れていればマージまたは rebase を提案)。
2. **差分の全体確認**: `git diff main...HEAD` で PR に含まれる全変更を確認する。
   意図しないファイル(生成物、一時ファイル)が混ざっていないか見る。
3. **サイズ確認**: 差分が大きい場合(目安 400 行超)は、分割できないか提案する。
4. **プッシュ**: `git push -u origin <branch>` する。
5. **PR 作成**:
   - タイトル: Conventional Commits 形式(例: `feat: add login rate limiting`)。
   - リポジトリに PR テンプレートがあればその構成に従う。なければ本文は以下の構成:
     - **Summary**: 何を・なぜ(1〜3 行)
     - **Changes**: 主な変更点の箇条書き
     - **Testing**: 動作確認・テストの内容
6. **セルフレビュー**: 作成後に PR の差分を最初から見直し、気づいた問題は
   マージ前に追いコミットで直す。

## 注意

- PR 本文に秘密情報・内部ホスト名を書かない。
- レビュー指摘への対応は、指摘単位でコミットを分けると追いやすい。
- マージ後はローカル・リモート両方のブランチを削除する。
